SEC 02
アーキテクチャ方針 ─ 3案比較と採用案
「両方納品」でもソースコードを2本立てる必要はない。ソース1セット・パッケージ2つ出力が最も保守性が高い。
案 ①
sys.platform 自動分岐
ファイル1個作業30-40分保守性△

main_v2.py 内に IS_PI = sys.platform.startswith("linux") を置いて if 文で切替。最小変更だが分岐がコード内に散る。

★ 採用案 ②
設定モジュール分離
ファイル4個作業45-60分保守性◎

定数だけ config_exe.py／config_pi.py に切り出し、app_config.py で OS判定して片方を import。main_v2.py 側は分岐ほぼなし。

案 ③ 不採用
完全別ファイル化
ファイル2個（独立）作業60分+毎回二重保守性×

main_exe.py / main_pi.py を完全に分ける。バグ修正・機能追加が二重作業になり事故の温床。共通ロジックが9割を占める本アプリでは非推奨。

補足
採用案②の根拠
仕様差7項目共通ロジック約9割

仕様差が7項目以上あるため①の散在分岐より②が見通し良い。新仕様追加も config側1行で済む。先方視点では完全に別パッケージに見える。

Day 1 / Step 4 ─ main_v2.py の修正（フルスクリーン）

変更前 L1047-1062 付近 / L2012 付近

def _fullscreen(self):
    is_zoomed = (self.root.state() == "zoomed")
    if not is_zoomed:
        self.root.state("zoomed")
    else:
        self.root.state("normal")

変更後

from app_config import FULLSCREEN_MODE

def _fullscreen(self):
    if FULLSCREEN_MODE == "fullscreen":
        cur = self.root.attributes("-fullscreen")
        self.root.attributes("-fullscreen", not cur)
    else:
        is_zoomed = (self.root.state() == "zoomed")
        self.root.state("normal" if is_zoomed else "zoomed")

def _exit_fullscreen(self):
    if FULLSCREEN_MODE == "fullscreen":
        self.root.attributes("-fullscreen", False)
    else:
        self.root.state("normal")
